# 서울 아파트 실거래가 대시보드 PRD

> **문서 버전** v1.0 · **작성일** 2026-08-12 · **구현 담당** Sonnet 에이전트 · **배포** GitHub Pages (정적)

---

## 1. 개요 및 목표

본 프로젝트는 2025년 7월 ~ 2026년 6월 서울시 25개 자치구 아파트 실거래 데이터(약 32만 건)를 개인 투자·매수 의사결정에 활용할 수 있도록 시각화하는 **정적 웹 대시보드**를 구축한다. 사용자는 데이터 분석 배경을 가진 개인 투자자로, "어느 구가 지금 상대적으로 저평가/과열되어 있는가", "최근 12개월 가격 추세가 상승인 지역은 어디인가", "관심 단지의 평형별 실거래 분포는 어떤가"를 스스로 탐색하기를 원한다. 서버·DB 없이 GitHub Pages에서 동작해야 하므로, **Python 빌드 스크립트가 CSV를 사전 집계해 경량 JSON(총 합계 2~3MB 수준)을 생성하고, 브라우저는 그 JSON만 fetch**하는 구조를 채택한다. 결과물은 기존 이력서 페이지(`/index.html`)와 공존하는 `/dashboard/` 경로의 다크모드 데이터 분석 도구다.

**성공 기준**
- 초기 로드(첫 화면 렌더 완료)까지 3초 이내, 최초 JSON 페이로드 500KB 이하(gzip 전)
- 25개 구 × 12개월 시세 비교·추이·지도 탐색이 새로고침 없이 클라이언트에서 완결
- 백엔드/빌드 툴체인(npm, webpack 등) 없이 `python build_data.py` 한 번 + git push로 배포 완료

## 2. 타겟 사용자 및 핵심 시나리오

### 2.1 페르소나
| 항목 | 내용 |
|---|---|
| 이름 | 개인 투자자 P (본 저장소 소유자) |
| 배경 | 데이터 분석 경험 보유. pandas·SQL에 익숙하며, 차트의 축·단위·표본 수(n)를 스스로 검증하려는 성향 |
| 목적 | 실거주 겸 투자 목적 아파트 매수 후보지 선별 |
| 디바이스 | 데스크톱 크롬 (1440px 이상) 주 사용, 모바일은 조회 수준의 보조 |
| 기대 | "예쁜 인포그래픽"이 아니라 **필터링 가능한 분석 도구**. 표본 수가 적은 통계는 그렇다고 표시해주기를 원함 |

### 2.2 핵심 시나리오
1. **S1 — 전체 조망**: 대시보드 진입 → 서울 전체 KPI(평균 평당가, 총 거래건수, 전월 대비 변동률)와 25개 구 choropleth를 보고 가격 지형을 한눈에 파악한다.
2. **S2 — 구 간 비교**: "강남 3구 말고, 평당가 대비 최근 6개월 상승률이 높은 구"를 찾기 위해 구별 랭킹 테이블을 상승률 기준으로 정렬하고, 최대 4개 구를 선택해 시계열 그래프에 겹쳐 본다.
3. **S3 — 구 드릴다운**: 관심 구(예: 성동구)를 클릭 → 해당 구의 동별 평당가 순위, 면적 구간별 가격 분포, 월별 거래량/가격 추이를 확인한다.
4. **S4 — 단지 탐색**: 검색창에 단지명(예: "래미안")을 입력 → 매칭된 단지 목록에서 하나를 선택해 최근 실거래 내역(계약일·면적·층·가격)을 표로 확인한다.
5. **S5 — 전월세 관점**: 딜타입을 '전세'로 전환해 동일한 지도·랭킹을 보고, 매매가 대비 전세가율(전세가/매매가)이 높은 구를 확인한다.

## 3. 정보구조 / 페이지 구성 (사이트맵)

**단일 페이지 애플리케이션(SPA) + 해시 라우팅**으로 구성한다. GitHub Pages는 서버 사이드 rewrite가 불가하므로 `history.pushState` 대신 **해시 라우팅(`#/...`)을 반드시 사용**한다.

```
/  (기존 index.html — 이력서. 상단에 "실거래가 대시보드" 링크 1개만 추가)
│
└── /dashboard/                     ← 대시보드 진입점 (dashboard/index.html)
     ├── #/overview                 [기본] 화면 A: 서울 전체 개요 + choropleth 지도
     ├── #/compare                  화면 B: 구 간 비교 (랭킹 테이블 + 다중 시계열)
     ├── #/gu/{구이름}              화면 C: 자치구 상세 드릴다운 (예: #/gu/성동구)
     ├── #/explore                  화면 D: 거래 탐색기 (필터 + 단지 검색 + 거래 테이블)
     └── #/about                    화면 E: 데이터 출처·정의·한계 (정적 텍스트)
```

**전역 UI 요소 (모든 화면 공통, 상단 고정)**
- 좌측: 로고/타이틀 "SEOUL APT · 실거래가 대시보드"
- 중앙: 탭 네비게이션 (개요 / 비교 / 탐색 / 정보)
- 우측 **글로벌 컨트롤 바** — 상태는 `localStorage` + URL 해시 쿼리스트링에 동기화
  - `dealType`: 세그먼트 컨트롤 [매매 | 전세 | 월세] (기본: 매매)
  - `period`: 드롭다운 [전체 12개월 | 최근 6개월 | 최근 3개월 | 개별 월 선택]
  - `metric`: 세그먼트 컨트롤 [평당가 | 거래금액] (기본: 평당가)
  - `areaBand`: 멀티셀렉트 [~60㎡ | 60~85㎡ | 85~102㎡ | 102~135㎡ | 135㎡~] (기본: 전체)

> **중요**: 글로벌 컨트롤 변경 시 페이지 전체 리로드 없이 현재 화면의 차트만 갱신한다. 상태는 `#/overview?deal=sale&period=6m&metric=ppp` 형태로 URL에 반영해 링크 공유가 가능해야 한다.

| ID | 컴포넌트 | 차트 종류 | 데이터 소스 | 상세 |
|---|---|---|---|---|
| KPI-1 | 서울 평균 평당가 | 숫자 + 스파크라인 | `summary.json.seoul.avg_price_per_pyeong` | "4,832만원/평", 하단 12개월 미니 라인(높이 32px, ECharts sparkline 옵션) |
| KPI-2 | 총 거래건수 | 숫자 | `summary.json.seoul.deal_count` | "72,459건 (2025.07~2026.06)" |
| KPI-3 | 전월 대비 변동률 | 숫자 + 화살표 | `summary.json.seoul.mom_pct` | 상승 시 `--pos`(레드 계열 아님 — §7 참조), 하락 시 `--neg` |

| **A-3** | 서울 월별 추이 | ECharts 콤보 (`bar` 거래량 + `line` 평균 평당가, `yAxisIndex` 2축) | `timeseries.json.seoul` | X축 12개 월, 좌축 평당가(만원), 우축 거래건수 |

**A-1 Choropleth 상세 스펙**
- 라이브러리: **ECharts 5 `geo`/`map` 시리즈** (Chart.js는 지도 미지원 → 지도는 ECharts로 통일)
- 지오메트리: `dashboard/data/geo/seoul-gu.geojson` (아래 §5.5 조달 방법 참조). 좌표계 WGS84, `properties.name`에 한글 구명(`"강남구"`) 필수.
- 등록: `echarts.registerMap('seoul', geoJson)` 후 `series: [{ type:'map', map:'seoul', nameProperty:'name' }]`
- 색상 매핑: `visualMap` 연속형, `min`/`max`는 현재 필터 결과의 5퍼센타일~95퍼센타일로 동적 계산. 색상 램프는 §7의 시퀀셜 팔레트(`--seq-1`~`--seq-6`) 사용.
- 라벨: `label: { show: true, formatter: '{b}', fontSize: 10, color: '#8B96A8' }` — 줌 레벨 무관 항상 표시.
- **인터랙션**
  - 호버: 툴팁에 `구명 / 평균 평당가 / 평균 거래가 / 거래건수 / 전월대비 %` 표시. 동시에 A-2 랭킹 바 차트의 해당 항목 하이라이트.
  - 클릭: `#/gu/{구이름}`으로 라우팅.
  - 우측 상단에 리셋(초기 뷰 복귀) 버튼. `roam: true`로 팬/줌 허용.
  - **표본 부족 처리**: 해당 필터 조합에서 `deal_count < 10`인 구는 `itemStyle.areaColor = '#2A3140'` (회색)으로 칠하고 툴팁에 "표본 부족 (n<10)" 표기.
- 반응형: 컨테이너 `ResizeObserver` → `chart.resize()`. 모바일(<768px)에서는 지도 높이 360px, 랭킹 차트는 지도 아래로 스택.

### 화면 D — 거래 탐색기 (`#/explore`)

**목적**: 개별 실거래 레코드 수준의 탐색과 단지 검색.

> **성능 원칙**: 32만 행 원본을 브라우저에 로드하지 않는다. 이 화면은 **단지 단위 집계(`complexes.json`)를 기본으로 탐색**하고, 사용자가 특정 단지를 선택했을 때만 그 단지의 개별 거래 내역을 담은 **샤딩된 JSON(`deals/{구}.json`)을 lazy fetch**한다. 구 단위 샤드는 최대 ~1.5MB(강남구 등) 수준으로, 클릭 시점에만 로드하면 문제없다.

| ID | 컴포넌트 | UI | 상세 |
|---|---|---|---|
| D-1 | 검색창 | 텍스트 입력 + 자동완성 드롭다운 | 단지명/동명 부분 문자열 매칭. 입력 200ms 디바운스. 대상은 `complexes.json`의 8,216개 레코드를 클라이언트 메모리에서 필터(라이브러리 불필요, `String.includes` + 초성 무시). 최대 20개 결과 표시 |

## 5. 데이터 파이프라인 설계

### 5.1 전체 흐름

```
seoul-apt-latest.csv (32만 행, 27MB)
        │
        ▼   python build_data.py     (표준 라이브러리 csv + statistics만 사용, pandas 선택적)
        │
        ├─► dashboard/data/summary.json          (~2KB)
        ├─► dashboard/data/by_gu.json            (~60KB)
        ├─► dashboard/data/timeseries.json       (~120KB)
        ├─► dashboard/data/complexes.json        (~900KB)
        ├─► dashboard/data/gu/{구이름}.json × 25 (~40KB each, lazy)
        ├─► dashboard/data/deals/{구이름}.json × 25 (~0.6~1.5MB each, lazy)
        └─► dashboard/data/meta.json             (~3KB)

dashboard/data/geo/seoul-gu.geojson  (수동 1회 배치, ~250KB simplified)
```

**빌드 산출물은 모두 git에 커밋**한다(GitHub Pages는 빌드를 실행하지 않음). `.gitignore`에 `dashboard/data/`를 넣지 말 것.

### 5.2 공통 규약

- **인코딩**: 모든 JSON은 UTF-8, `ensure_ascii=False`, `separators=(',',':')` (공백 제거로 용량 절감)
- **금액 단위**: 원본 CSV와 동일하게 **만원 단위 정수**. 표시 변환(억원)은 프론트엔드 책임
- **반올림**: 평균값은 소수점 0자리 정수로 반올림, 비율(%)은 소수점 2자리
- **결측**: 값이 없으면 `null` (빈 문자열/0 금지)
- **키 명명**: `snake_case` 고정
- **deal_type 코드화**: `"매매"→"sale"`, `"전세"→"jeonse"`, `"월세"→"wolse"` (JSON 키로 사용, 한글 키 회피)
- **면적 구간 코드**: `"a60"`(~60㎡ 미만), `"a85"`(60~85), `"a102"`(85~102), `"a135"`(102~135), `"a135p"`(135 이상)
- **기간 코드**: `"all"`(12개월), `"m6"`(최근 6개월: 2026-01~2026-06), `"m3"`(2026-04~2026-06)
- **최소 표본**: 집계 시 `deal_count < 10`인 조합은 통계값을 `null`로 채우되 `deal_count`는 실제 값 유지

### 5.3 파일별 스키마

(전체 스키마 상세는 Opus 기획 세션 원문 참조 — meta.json / summary.json / by_gu.json / timeseries.json / gu/{구}.json / complexes.json / deals/{구}.json 7종)

### 5.4 `build_data.py` 구현 요건

- 위치: 저장소 루트 `build_data.py` (기존 `analyze.py`는 그대로 두고 건드리지 않는다)
- 의존성: **Python 표준 라이브러리만** (`csv`, `json`, `statistics`, `collections`, `datetime`, `pathlib`, `os`)
- 구조: CSV를 **1회 스트리밍 순회**하며 조합별 합계·건수를 적재
- 실행 후 콘솔에 생성 파일 목록과 크기(KB) 출력, 2MB 초과 시 경고
- 멱등성: 재실행 시 기존 파일 덮어쓰기
- 데이터 정합성 가드: 결측/이상치 행 스킵 + 스킵 건수 로그

### 5.5 GeoJSON 조달

1. 1순위: 공개 서울 자치구 경계 GeoJSON을 다운로드해 `tools/prepare_geo.py`로 25개 구만 필터링, `properties.name`을 한글 구명으로 정규화 후 `dashboard/data/geo/seoul-gu.geojson`으로 커밋 (런타임 외부 fetch 금지)
2. 좌표 단순화로 250KB 내외로 축소
3. 확보 실패 시 폴백: 5×5 타일 카토그램(HTML 그리드 + CSS)
4. `properties.name` 25개가 `meta.json.gu_list`와 정확히 일치하는지 빌드 스크립트에서 assert

## 9. 구현 단계별 작업 순서

- **Phase 0** 준비 — 디렉터리/`.nojekyll` 생성, CSV 값 검증

- **Phase 3** 셸 + 디자인 시스템 (tokens.css, 라우터, 상태 스토어, data 로더)

- **Phase 5** 화면 B 비교
- **Phase 6** 화면 C 구 상세

**MVP 기준**: Phase 0~4 완료 시점 (개요 화면 + 데이터 파이프라인)이 최소 사용 가능한 제품.
